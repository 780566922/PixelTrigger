# PixelTrigger

> 像素触发器 · 蓝线识别自动翻页

一个跨平台应用（macOS / Windows），通过识别屏幕上指定区域的像素颜色变化，自动触发滚动或按键操作。典型用途是乐谱软件（如 MuseScore）的自动翻页：检测到播放光标经过指定区域后，自动向上/向下滚动页面。

## 功能

- **简化模式（默认）**：小窗口，只有「检测区域预览 + 状态 + 开始/停止」，
  常驻在乐谱旁边不挡事；点右上角「⚙ 完整设置」随时切到全参数界面
- **快捷键启停**：窗口内 `⌘↩`（Windows `Ctrl+Enter`）开始/停止；
  macOS 还支持**全局** `⌃⌥↩`，在别的软件里也能直接启停
- 像素颜色识别：支持 7 种预设色系 + 精准容差模式
- 两种触发方式：滚动翻页、按键触发
- 智能冷却：触发后自动暂停检测
- 实时预览：实时显示监控区域截图
- 参数实时生效：运行中修改参数立即生效
- **参数自动保存**：改完 0.6 秒自动落盘，顶栏显示「✓ 已保存」，
  点它可在文件夹中定位配置文件
- 内存截图：无磁盘 I/O，帧耗时 10~50ms
- **全像素稠密检测**：向量化扫描，单帧约 0.2ms，1px 细线也不会漏检
- 多屏支持：主屏/副屏都能框选监控区域
- 外观自动跟随：系统浅色/深色切换后 1 秒内自动换肤，无需重启

## 下载安装

### macOS

1. 从 Releases 页面下载最新的 `PixelTrigger-1.3.1.dmg`（或 `PixelTrigger.app.zip`）
2. 打开 DMG，把 PixelTrigger 拖到「应用程序」文件夹；或解压 zip 后手动拖入
3. 第一次打开：右键点击 App，选择「打开」，弹窗里再点「打开」
4. 授权：
   - 首次点击「开始监控」或右上角权限红点时，应用会**主动弹出系统授权框**，
     点「允许」即可（屏幕录制 + 辅助功能各弹一次）；
   - 也可手动：系统设置 → 隐私与安全性 → 屏幕录制 / 辅助功能，勾选 PixelTrigger
5. 完全退出 App（Cmd+Q）再重新打开

> **关于「设置里没有 PixelTrigger 条目」**：macOS 的规则是——应用必须主动调用
> 权限请求 API，系统才会弹出授权框、并在设置里生成该应用的条目。本应用已支持：
> 点右上角红点或「开始监控」时会主动请求权限，弹框出现后设置里就会有条目了。
> 若仍未出现，先确认 App 已拖到「应用程序」目录（见下方提示），再点一次红点。

> 未做公证（notarization），首次打开需按上述步骤手动放行。若提示"无法验证开发者"，
> 可在终端执行 `xattr -cr /Applications/PixelTrigger.app` 后重试。

> **务必拖到「应用程序」后再运行**：从 DMG 磁盘映像（挂载卷 `/Volumes/...`）
> **直接双击运行**是权限红点不变绿的最常见原因。DMG 卷是只读的、挂载路径也不稳定
> （重复挂载会变成 `/Volumes/PixelTrigger 1` 等），系统无法给它稳定记录权限授权。
> 请把 App 拖到「应用程序」文件夹，再从那里打开。

> **更新应用后权限可能失效**：本应用使用 ad-hoc 签名（无开发者证书），每次更新后
> 二进制签名会变化，macOS 会把旧的辅助功能/屏幕录制授权视为「不再匹配」，
> 表现为系统设置里仍显示已勾选、但应用右上角红点不变绿。
> 解决办法：在系统设置里**取消勾选 → 重新勾选**一次即可（无需卸载）。

### Windows

1. 从 Releases 页面下载最新的 `PixelTrigger.exe`（单文件，免安装）
2. 直接双击运行。首次运行若被 SmartScreen 拦截，点「更多信息 → 仍要运行」即可
   （应用未做代码签名，属正常提示）
3. Windows 上**无需授予任何权限**，打开后直接框选区域、点「开始监控」即可

> **高 DPI / 显示缩放**：应用在启动时声明 Per-Monitor DPI Aware，
> 缩放（125% / 150% / 200%）与高刷新率高分屏下框选区域与实际监控
> 区域保持一致（v1.2.1 修复：旧版在缩放屏幕上框选会偏移）。
> 若遇到坐标异常，可在源码目录运行 `python dpi_diag.py --grab`
> 输出各坐标源的诊断信息，便于反馈定位。

### Windows 滚动怎么调

Windows 的滚轮事件以「格」为单位（一格 = `WHEEL_DELTA` = 120），而
macOS 的 `CGEvent` 是像素级滚动。两者的关键差异在于：

- **macOS**：可逐帧下发任意像素量，滚动天然连续平滑；
- **Windows**：滚轮最小量子是「一格」，且 `mouse_event` 的 `dwData` 是
  32 位无符号整数——把「亚格微增量」（远小于 120）或「多格大值」（如
  ±240）经 `mouse_event` 传进去，幅度会被压平，导致「总距离」与
  「实际滚动量」脱钩。

因此 v1.2.6 起，Windows 改用 **PostMessage 直投 `WM_MOUSEWHEEL`**：
它的 `wheelDelta`（wParam 高 16 位）是**有符号值**，亚格增量能原样
传递。于是缓动曲线每一帧的小步进都能直接变成连续的微小滚轮增量，
滚动**像触摸板一样连续顺滑**，同时「总距离」严格线性决定跨度。

| 控件 | 说明 |
|---|---|
| **总距离** | 一次翻页的基础跨度，**改完立即生效**，严格决定滚动量。 |
| **总时长** | 动画时长，**改完立即生效**，只影响快慢、不影响跨度。 |
| **滚动密度** | 1.0 = 每 100 像素 1 格。**默认 1.0 即足够顺滑**，一般无需改动。 |
| **试滚** | 用当前参数立即滚动一次，不必等颜色触发即可反复对照调参。 |
| **生效 ≈ N 格 / 次** | 读的是**监控线程真正会用的运行时快照**，它一变就说明参数已被采纳。 |

调参建议：

1. 用「试滚」观察目标程序的反应，边看右侧的「生效 ≈ N 格 / 次」边调；
2. 先定「总距离」——它是你想要的滚动跨度，改到目标位置恰好滚到；
3. 「滚动密度」默认 1.0 已顺滑，若目标程序本身自带滚动动画（部分
   乐谱 / 阅读软件），减小总距离反而可能更稳。

> **⚠️ 兼容性说明**：亚格直发依赖目标程序按 `delta/120.0` 浮点累加滚轮
> 增量，绝大多数现代程序（Qt / Electron / WPF / UWP 等）都支持。若目标
> 程序是老式 `int(delta/120)` 整数截断实现，可能出现「完全滚不动」的情况，
> 届时请在 Issues 反馈（可加一个整格兼容模式切回）。

> **怎么确认改动生效了？** 两个信号：
> 1. 「滚动密度」右侧的 **`生效 ≈ N 格 / 次`** 会随输入实时变化；
> 2. 停止输入约 0.7 秒后，日志区会出现一条
>    **`⚙ 参数已生效：总距离 … / 总时长 … 秒 → 约 … 格 / 次`**。
>
> 窗口左上角标题旁显示 **`v1.3.1`** 这类版本号，可用来确认自己跑的是
> 哪个构建（历史上有过一次「以为测的是新版、其实还是旧版」的来回）。

> **v1.3.1 修复**：
> 1. **「按住拖拽框选后，屏幕一直卡在半透明遮罩上退不出去」**。遮罩是
>    override-redirect + 半透明 + 置顶的窗口，在 `<ButtonRelease>` 回调里直接
>    销毁它，macOS 上偶发只拆掉了 Tcl 对象、NSWindow 留在屏幕上 —— 区域其实
>    已经保存，人却被一层点不动的黑纱困住。现在改为**先 `withdraw()`（同步
>    从屏幕移除）→ 立即回填结果并唤醒调用方 → `after_idle` 再真正
>    `destroy()`**，任何一步失败都不影响退出。
> 2. **框选遮罩会抢键盘焦点**：override-redirect 窗口默认不激活应用，
>    导致之前按 `ESC` 会被送到前台别的程序、遮罩退不掉。现在遮罩打开时主动
>    抢焦点，`ESC` 取消随时可用。
> 3. **额外的保险**：新增一路兜底轮询，每 120ms 向系统查询「左键是否还按着」。
>    万一 `<ButtonRelease>` 事件本身丢失，程序会自己补一次松手并按最后
>    指针位置完成框选，绝不让遮罩把用户困住。拖拽、两次点击、`ESC` 取消
>    三条路径均已自动化验证。
>
> **v1.3.0 新增**：
> 1. **简化模式（默认界面）**：窗口缩到约 420×380，只保留「检测区域预览 +
>    状态 + 开始/停止」。双击预览可重新框选区域；点右上角「⚙ 完整设置」
>    切到全参数界面，完整模式里点「🗕 简化模式」再缩回来。上次用的模式会
>    被记住（配置项 `ui_mode`）。
> 2. **快捷键**：窗口内 `⌘↩` / `Ctrl+Enter` 开始或停止；macOS 额外支持
>    全局 `⌃⌥↩`（CGEventTap 监听，需要「辅助功能」权限；未授权时会在
>    授予后自动重试，期间不影响其他功能）。Windows 版暂只提供窗口内快捷键。
>
> **v1.2.7 修复**：
> 1. **「保存了配置，下次打开却没了 / 不生效」**。根因是保存时把数值统一
>    写成 `str(float(...))`，`1062` 落盘成 `"1062.0"`；下次启动加载回来，
>    监控线程里的 `int("1062.0")` 直接抛 `ValueError`，被外层 `except`
>    静默吞掉 —— 界面一切正常，实际一帧都没扫。现已改为「保存时归一化成
>    最简写法（`498`），读取时一律走容错解析（`to_int / to_float`）」，
>    并在区域非法时给出明确日志提示而不是静默跳过。
> 2. **改成「改动即存」**：参数改动 0.6 秒后自动落盘，顶栏实时显示
>    `✓ 已自动保存 12:34:56`（点它可在文件夹中定位 `config.json`）。
>    退出时不再弹「是否保存」对话框——那个对话框恰恰是最容易丢配置的
>    环节（点取消、被模态窗口挡住、Cmd+Q 直接绕过都会丢）。
> 3. **检测更稠密且更快**：`scan_region` 从「Python 逐像素比较 + 每隔
>    step 行才扫一行」改为 PIL 向量化掩膜（`point` 查表 + `darker` 求交 +
>    `bytes.count` 统计）。283×118 区域单帧从 ~10ms 降到 **0.23ms**，
>    因此默认对**每一个像素**都判定，细到 1px 的蓝线也不会漏检。

> **v1.2.6 修复**：上一版（v1.2.5）为修「总距离失效」改成「整格累积」，
> 默认每格 100 像素，导致缓动曲线每帧几像素的小步进攒不满一格、大部分
> 帧不发事件，600px 被压成 6 次离散跳动，观感一卡一卡。现已改用
> PostMessage 直投亚格增量，同样的 600px 变成 68 次连续微动（单次 1~27），
> 跨度仍精确不变，实现触摸板级顺滑。

> **v1.2.5 修复**：上一版（v1.2.4）把「总距离」拆成每帧 ±1~±27 的
> 亚格微增量下发，这些微小增量经 `mouse_event` 的 DWORD 无符号参数
> 传递后，下游程序读到的高 16 位只剩方向、幅度被压平，加上部分程序按
> 整格截断，最终「总距离」与「实际滚动量」脱钩——用户实测「把总距离
> 改到 600 反而滚得更短」。现已改为整格累积、每次发标准 ±120，恢复
> 「总距离 → 格数」的严格线性。
>
> **v1.2.4**：把「是否已生效」做成可见反馈（上面的两个信号）+ 界面显示
> 版本号；另外「总时长」此前无法即时生效的问题也已随 v1.2.3 一并修复。
>
> **v1.2.3 修复**：此前只有「滚动密度」是输入即生效的，改动「总距离 /
> 总时长」必须重启监控才会被读取，表现为这两个参数「失效」。原因是
> 参数输入框从未挂 `trace`，运行时快照只在少数控件回调里刷新，监控线程
> 读到的始终是启动时的旧值。现已让所有参数框都即时刷新运行时快照。
>
> **v1.2.2 的「整格」开关已移除**：实测勾选后滚动距离突增、密度调节
> 失去意义，且观感更卡，属反向优化。

> 该 exe 由 GitHub Actions 在云端 Windows 环境自动构建（`PyInstaller` 不支持
> 交叉编译，Windows 程序只能在 Windows 上打包），配置见
> `.github/workflows/build-windows.yml`。

## 使用方法

1. 打开 PixelTrigger
2. 选择「色系匹配」或「精准容差」模式
3. 点击「点击框选屏幕区域」，框选监控区域
4. 选择触发方式（滚动翻页 / 触发按键）
5. 点击「开始监控」

- 日志区保留最近 2000 行，超出后自动丢弃最旧的，长时间运行不会持续吃内存

## 外观跟随系统

应用每1 秒读一次系统外观设置（`AppleInterfaceStyle`，走 CFPreferences进程内读取），
与当前主题不一致就换肤并重建界面。

换肤是重建整棵控件树，不是改颜色变量 —— Tk 的 `bg`/`fg` 在控件构造时就已固化，
事后改模块常量对已存在的控件无效。因此重建时会先把当前状态整体快照再还原，
以下内容跨切换完整保留：

- 所有输入框与下拉参数、色系/容差/精准RGB、按键组合
- 面板显隐（识别模式、触发方式、按键动作三组联动）
- 运行状态：监控是否在跑、开始/停止按钮可用性、状态灯颜色、冷却剩余
- 日志区全部历史、区域预览图

两点行为说明：

- 主题切换**不写入配置文件**，只影响显示；退出时「参数是否修改」的判定基线
  保持为启动时的快照，所以改过的参数该提示保存时依然会提示。
- 捐赠弹窗、按键捕获框、屏幕框选与取色器（全屏覆盖层）打开期间会**推迟**换肤，
  关闭后自动补上。这是为了避免重建界面打断正在进行的交互。

## 自行打包

### macOS（.app / .dmg）

推荐使用仓库内置的一键打包脚本：

```bash
./build_app.sh               # 生成 dist/PixelTrigger.app
./build_app.sh --dmg         # 同时生成 dist/PixelTrigger-1.3.1.dmg
```

脚本会自动完成：创建隔离的构建虚拟环境、安装依赖、应用 py2app 兼容补丁、
打包、补 stdlib 锚点、运行时自举验证、ad-hoc 签名。

> **不要用 `/usr/bin/python3` 打包。** CommandLineTools 自带的 Python 3.9 的
> Tcl/Tk 与 macOS 15.7 不兼容，py2app 探测 Tk 版本时会直接崩溃。脚本使用的是
> `python3.12`（Tk 9.0）。

### 手动打包

```bash
python3.12 -m venv .build/venv
.build/venv/bin/pip install py2app Pillow \
    pyobjc-framework-Quartz pyobjc-framework-ApplicationServices
.build/venv/bin/python setup.py py2app
ln -sfn ../Resources/lib dist/PixelTrigger.app/Contents/MacOS/lib
codesign --force --deep --sign - dist/PixelTrigger.app
```

产物在 `dist/PixelTrigger.app`。

### Windows（.exe）

在 Windows 上双击 `build_win.bat`（或在命令行执行），脚本会自动创建虚拟环境、
安装 PyInstaller 与 Pillow，并打包出单文件 `dist\PixelTrigger.exe`：

```bat
build_win.bat
```

> Windows 的 exe **必须在 Windows 上打包**（PyInstaller 不支持交叉编译）。
> 仓库已配置 GitHub Actions，推送到 main 或打 tag 时会在云端 Windows 机器
> 自动构建，产物可在仓库的 Actions → Build Windows EXE → Artifacts 下载。

## 跨平台架构

系统级差异（截图、键鼠模拟、显示器枚举、系统深浅色、权限、配置目录）全部收口在
`platform_backend.py`，主程序 `color_watcher.py` 保持平台无关：

| 能力 | macOS | Windows |
|---|---|---|
| 屏幕截图 | Quartz.CGWindowListCreateImage | GDI BitBlt（ctypes），ImageGrab 兜底 |
| 滚轮 / 键盘 | CGEvent | mouse_event / keybd_event |
| 显示器枚举 | CGGetActiveDisplayList | EnumDisplayMonitors |
| 系统深浅色 | CFPreferences | 注册表 AppsUseLightTheme |
| 权限 | TCC（屏幕录制 + 辅助功能） | 无（无需授权） |
| 配置目录 | ~/Library/Application Support | %APPDATA% |
